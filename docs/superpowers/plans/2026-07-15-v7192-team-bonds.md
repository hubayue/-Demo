# v7.19.2 Team Modifiers and Bonds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Godot v7.19.2 formation choices affect real combat through class counts, cell traits, formation aura, field bonuses, and all 18 same-field bonds.

**Architecture:** Add a focused `BattleTeam` rules object that derives team counts, active bonds, per-hero bond effects, and final attack modifiers from a `BattleRun`. `BattleRun` remains the simulation owner and delegates damage/rate calculations to this object; the UI only reads active-bond state. Browser-runtime fixtures from the frozen v7.19.2 page are the parity authority.

**Tech Stack:** Godot 4.7, GDScript, frozen Web v7.19.2, Playwright CLI, deterministic JSON fixtures, headless SceneTree tests.

- [x] **Step 3: Implement `BattleTeam`**

Create a rules object with this public surface:

```gdscript
class_name BattleTeam
extends RefCounted

var catalog
var counts: Dictionary = {}
var active_bonds: Dictionary = {}

func recompute(run) -> void
func active_bond_ids() -> Array
func bond_fx(run, hero_id: String) -> Dictionary
func unit_mods(run, unit: Dictionary) -> Dictionary
func unit_damage(run, unit: Dictionary, mods: Dictionary) -> int
func unit_rate(unit: Dictionary, mods: Dictionary) -> float
```

`recompute()` counts every unit class and activates a bond only when all member IDs are present. `bond_fx()` multiplies only bonds containing the requested hero; Jinlan and `tuanjie` amplify the bonus above 1, not the full multiplier. The retired `need` field must not gate activation.


Both fixed and random placement must call `team.recompute(self)` after a successful change. Starting a run initializes an empty team and then recomputes after the opening hero is placed.
