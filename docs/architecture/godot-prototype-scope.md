# Godot 设计原型工程边界

## 目标

本工程把老板当前 Web Demo 转化为可持续迭代的 Godot 单机设计原型。第一验收阶段不是“近似实现”或“流程跑通”，而是先完整复现老板 Demo 的可观察体验；只有复现基线通过后，玩法优化才使用独立分支开展。

当前权威版本见 `docs/baseline/CURRENT_AUTHORITY.md`。

## 必须完全复现

- 480×800 页面构图、信息层级、颜色、控件尺寸与可点击区域。
- 首页、周地图、主公、武将、战斗、结算等全部单机页面和流程。
- 15 格阵地、障碍、武将拖动/换位/售出/查看及鼠标与触摸反馈。
- 武将、主公、敌方渠帅、特种敌军、地形、天气、遗宝、战术和无尽规则。
- 普攻、绝技、弹道、范围提示、飘字、状态、受击、死亡和音效事件。
- 当前 Web 版本更新日志中已生效的行为。

## 单机替代项

- 不搭建登录、注册、云存档、战报和真实排行榜服务器。
- 本地存档写入 `user://`，固定样例用于展示排行榜和公共资料。
- 替代仅改变数据来源；凡玩家能看到或操作的页面仍需与 Web 基线一致，并明确标识演示数据。

## 工程原则

1. 原始 Web 源码冻结保存，不在基线目录直接重构。
2. 规则状态、表现绘制和输入状态机分离，避免继续扩张单文件绘制器。
3. 每个页面或战斗行为均提供固定状态、自动测试、Godot 实机截图和 Web 对照记录。
4. 旧版本测试可以保留追溯价值，但不能代替当前版本验收。
5. 只有 `docs/parity/v7.19.14-exact-parity-matrix.md` 对应项的四类证据齐全，才可标记完成。

## 明确不做

- 线上账号与权限系统。
- 云数据库、云档案同步和真实玩家排行榜。
- 为未知服务端接口保持兼容。
- 在老板基线尚未复现前，把实验性优化混入基线分支。
