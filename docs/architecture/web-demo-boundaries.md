# Web Demo 重构边界

## 当前结构

`v7.18.8` 已从单一 HTML 文件机械拆成页面壳、样式和运行脚本。拆分没有改变执行顺序、玩法数据、输入、网络协议或 Canvas 表现。

当前最大的剩余问题仍是 `web-demo/src/main.js`：战斗规则、内容数据、状态、绘制、输入、音效、账号和云存档共用同一作用域。

静态依赖信号：

- `state.*` 引用约 1578 处；这是主要耦合中心。
- `ctx.*` 调用约 2307 处；绘制与玩法流程尚未隔离。
- `Math.random()` 约 48 处，`Date.now()` 约 13 处；当前战局难以确定性重放。
- 浏览器缓存调用约 5 处，同源 `fetch()` 调用约 3 处。
- 主循环由 `requestAnimationFrame()` 驱动，核心战斗入口为 `update(dt)`，绘制入口为 `draw()`。

这些数字用于确定提取顺序，不代表性能问题已经被实测证明。

## 目标边界与提取顺序

### 1. 账号与服务器适配器

职责：封装 `/api/register`、`/api/login`、`/api/load`、`/api/save`、`/api/battle`、`/api/board` 和 `/api/version`。

约束：

- 玩法代码不得直接调用 `fetch()`。
- 接口返回值先保持现有字段和错误语义，不在重构阶段改协议。
- Godot 侧用 `HTTPRequest` 实现同一接口；若拿不到服务器源码，服务端仍作为外部黑盒。

### 2. 本地缓存与存档规整

职责：隔离 `localStorage`、断网缓存、默认档创建、旧档规整和存档序列化。

约束：

- 输入和输出必须是可序列化对象。
- 规整函数不得读取 Canvas、DOM 或网络状态。
- Web 与 Godot 必须共享一份字段说明和迁移样例，避免两个版本各自解释存档。

### 3. 静态内容数据

职责：英雄、羁绊、主公、遗物、战场、关卡、敌军、成就和成长配置。

约束：

- 纯数据与带行为的函数分开。
- ID 是跨 Web、Godot、存档和服务器记录的稳定协议，不因显示名或文件重排而改变。
- 第一阶段保持现有 JavaScript 数据；验证无行为差异后，再转换成 JSON 或 Godot Resource。

### 4. 可确定性的领域规则

职责：星级、伤害、克制、成长、计分、卡池权重、波次参数和奖励计算。

约束：

- 纯函数只接收参数并返回结果，不直接读取 `state`、时间、随机数、DOM 或 Canvas。
- 需要随机性的规则显式接收随机源。
- 需要时间的规则显式接收时间或 `dt`。
- 每条被提取规则先用当前实现样例写失败测试，再迁移实现。

`web-demo/src/core/progression.js` 是第一条已完成的边界。

### 5. 战斗状态与模拟

职责：战局状态、单位状态、波次推进、伤害结算、技能效果和胜负条件。

约束：

- 模拟层不调用 `ctx`、DOM、音频或网络。
- 模拟结果通过事件描述视觉和音效，例如 `damage_dealt`、`unit_died`、`skill_cast`。
- 固定随机种子和固定输入序列应能够重放相同战斗结果。
- Web 与 Godot 以相同场景样例对照关键帧状态，而不是只对比截图。

### 6. Canvas 绘制与表现

职责：把只读战斗快照和表现事件绘制到 480×800 逻辑画布。

约束：

- 绘制函数不修改核心玩法状态。
- 粒子、抖动、飘字等纯表现状态可以保留在渲染层。
- 性能优化必须先记录帧耗时、实体数量和分配热点，再决定缓存、对象池或批处理。

### 7. 输入与页面导航

职责：指针、触摸、键盘、拖放、弹窗和页面切换，并转换成明确的游戏动作。

约束：

- 输入层提交动作，不直接执行伤害、奖励或存档计算。
- 同一动作模型将映射到 Godot 的 `_unhandled_input` 和 `Control` 信号。

## Godot 对接合同

| Web 边界 | Godot 目标 |
| --- | --- |
| `src/core/*.js` 纯规则 | 无场景依赖的 GDScript 类或静态函数 |
| 静态内容数据 | JSON 或自定义 `Resource` |
| 可序列化战斗状态 | `RefCounted`/`Resource` 状态对象 |
| `update(dt)` 模拟 | 固定步长战斗模拟节点 |
| Canvas 绘制 | `Node2D`、`Control` 与自定义 `_draw()` |
| 输入动作 | `_unhandled_input` 与 UI 信号 |
| 账号 API | `HTTPRequest` 适配器 |
| 本地缓存 | `user://` 存档适配器 |

Godot 实现不得直接逐行翻译当前单体脚本。每个系统只有在 Web 侧已经形成“可序列化数据 + 可测试纯规则 + 明确输入输出”后才进入对应的 Godot 迁移任务。

## 阶段验收

每次提取必须同时满足：

1. 新规则测试先失败、实现后通过。
2. 全量 `npm test` 无失败和警告。
3. 本地页面真实浏览器加载无新增控制台错误。
4. 对应关键流程与 `demo-v7.18.8-baseline` 行为一致。
5. 单独 Git 提交，能够独立回退。
