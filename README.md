# Demo 原型重构与 Godot 迁移

本仓库用于保存当前 Demo 的原始源码、架构重构版本，以及后续 Godot 4 迁移版本。

## 工作原则

1. 原始 Demo 首先以可运行的基线版本入库，保留行为证据，不直接覆盖。
2. 先建立体验清单、运行记录和关键流程测试，再进行源码重构。
3. 重构阶段只改善结构、性能和可维护性，不主动改变玩法。
4. Godot 迁移作为独立阶段实施，以同一套体验验收清单进行对照。
5. 每个可验证的小阶段单独提交，确保可以回退和定位差异。

## 计划阶段

- 阶段 0：接收源码并复现当前 Demo。
- 阶段 1：冻结体验基线，记录流程、输入、数值、画面和音频表现。
- 阶段 2：为现有技术栈补齐测试与性能基准，并进行渐进式重构。
- 阶段 3：确定 Godot 4 项目结构，逐系统迁移。
- 阶段 4：执行双版本对照验收、性能验收和导出验证。
