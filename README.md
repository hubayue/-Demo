# Demo 原型重构与 Godot 迁移

本仓库用于保存老板当前 Demo 的原始源码、行为基线，以及用于玩法调整和方案演示的 Godot 4 离线原型。

## 工作原则

1. 原始 Demo 首先以可运行的基线版本入库，保留行为证据，不直接覆盖。
2. 先建立体验清单、运行记录和关键流程测试，再进行源码重构。
3. 老板基线保持不变；玩法实验使用独立场景、配置和提交，不能覆盖基线证据。
4. Godot 是后续主要原型载体，以可玩对照而不是服务器兼容作为验收标准。
5. 每个可验证的小阶段单独提交，确保可以回退和定位差异。

## 计划阶段

- 阶段 0：接收源码并复现当前 Demo。
- 阶段 1：冻结体验基线，记录流程、输入、数值、画面和音频表现。
- 阶段 2：从 Web 基线提取高价值规则、数据和体验约束。
- 阶段 3：在 Godot 中建立离线、可重置、可复现的设计原型框架。
- 阶段 4：围绕具体体验问题制作方案分支，并与老板基线对照验收。
